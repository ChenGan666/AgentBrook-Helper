本次更新重点：IM 连接（新功能）——手机上的 Telegram 直接和你的 Helper 对话，工具能力与主界面完全一致。

【IM 连接（新功能 · 首发 Telegram）】
- 设置 → IM 连接：安装 Telegram 通道插件 → 按引导在 @BotFather 创建 Bot、粘贴 Token、一键测试连接 → 保存并启用，手机即可开始对话
- 免公网、免隧道：桌面端用长轮询接收消息，无需公网 IP、无需端口映射，合规稳定
- 私聊专用：默认只处理与 Bot 的私聊；陌生聊天按配对规则处理，群聊暂不开放
- 通道插件热插拔：IM 通道以插件形式安装/卸载，随插件目录加载，主程序不内置平台实现；后续可扩展更多 IM（桥接通道已就绪，可对接微信/WhatsApp 等外部桥）

【同权执行（IM 消息 = 你在主界面的输入）】
- 手机发来的消息走与主界面完全相同的 Agent 回合：多轮工具调用、终端命令、文件读写、查资料、生成媒体全部可用
- 执行过程在主窗口实时可见；需要授权的操作按当前授权模式处理（IM 来源按"用户本人通道即授权"自动放行并留痕）
- 只把最终结果回给手机，过程细节不外发；多轮工具回合的完整正文都会送达，不会只剩最后一段

【双向会话（手机 ↔ 桌面同一会话）】
- 每个 IM 聊天自动对应一个专属会话，出现在主窗口会话列表（有则复用、无则新建），标题形如「你的名字［telegram］」
- 主窗口可以直接在该会话里输入，结果同样发送到手机
- 手机发消息时，主窗口该会话自动刷新最新往来（无需切换会话、无需重启）
- 附件与指令分条发送也支持：附件先确认「已收到附件，等待具体指令」，随后你发出具体指令（如"把这几张图合成一张"），助手带着这些附件执行

【附件双向传递（新功能）】
- 手机发图片：图片进入会话并内嵌显示（自适应缩放），模型按当前所选模型的能力解析图片内容；模型不支持图片理解时会明确提示切换模型，不会答非所问
- 产物回传：助手生成的文件（截图文稿、图表、报告等）直接发回手机（照片/文件两种形态自动选择）
- 收到附件失败（超限/下载失败/过期）会明确告知并提示重发，不会静默丢失

【模型能力属性（模型设置）】
- 模型列表现在记录服务端返回的输入能力（如 text / image / video）与模型类型
- 附件能力判断以该属性为准：所选模型支持图片理解才解析图片；图像生成模型（如 qwen-image）不承担图片理解
- 解析使用的模型与你主界面当前所选模型一致

【其他改进】
- 会话删除更彻底：删除 IM 会话后，同一聊天的新消息会开启全新会话（旧会话归档，不会被"复活"）
- 会话界面附件行内嵌图片；文件行可点击用系统程序打开
- 修复启动时偶发的残留终端卡（模型列表自动刷新提示改为气泡提示）
- 修复多轮工具回复只送达最后一段、会话内容重复、重新打开会话后附件显示异常等问题
